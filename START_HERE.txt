================================================================================
                       CRITICAL ISSUE SUMMARY
================================================================================

THE PROBLEM:
  When typing in the "Add Card" form, focus is lost after the first character.

THE CAUSE:
  The PHPX framework replaces entire innerHTML on state updates. When the
  priority select changes, the entire component re-renders, destroying the
  input DOM node and causing focus loss.

THE WORKAROUND:
  The form uses uncontrolled inputs that read their value from the DOM
  directly, avoiding some state updates. But the focus issue persists.

THE SOLUTION:
  Requires either:
  1. Virtual DOM implementation (like React)
  2. Framework-level partial updates
  3. Component architecture changes

THIS IS NOT A BUG IN THE CODE:
  It's a fundamental framework limitation that affects all form-heavy apps.
  It's a great teaching tool for understanding full re-render vs Virtual DOM.

================================================================================
                         KEY INSIGHTS
================================================================================

1. PHPX = JSX FOR PHP
   Use React-like syntax in PHP. Compiles to standard PHP, then to WASM.

2. FULL RE-RENDER MODEL
   Every state change = entire component re-renders. No Virtual DOM.
   This is why focus is lost - the input DOM node is recreated.

3. VRZNO BRIDGE
   Direct JavaScript DOM access from PHP. Direct property access is 4-6x
   faster than vrzno_eval() for writes. Benchmark tool included!

4. EVENT HANDLERS ARE PHP
   onClick={fn($e) => ...} - Use PHP syntax, not JavaScript.
   $e->preventDefault(), $e->target->value, etc. all work.

5. STATE MANAGEMENT WITH HOOKS
   useState() like React. Proper closure capture. Callbacks for prop flow.

   The proper fix is implementing a Virtual DOM like React. That's a major
   architectural change but solves many issues.
